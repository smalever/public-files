# Проверки CLI и технические ограничения

Загружай эту справку при обслуживании CLI, изменении справочника или разборе сбоя. Для обычной записи еды она не нужна.

## Подтверждённый результат

- `meal`: успех только при `status: ok, saved: true, verified: true`. CLI новым read-only соединением проверяет запись приёма и полный список позиций после commit.
- `alias-add`: `created, saved: true, verified: true` — добавлено; `already_exists, saved: false, verified: true` — существующая связь проверена, дубль не создавался.
- `product-update`, `alias-update`: успех — `status: ok, saved: true, verified: true, backup_removed: true`.
- Код выхода 0 без нужных JSON-полей не доказывает запись. После проверенного receipt повторное чтение той же записи не нужно.
- При `saved: true, verified: false` запись уже сохранена, но не подтверждена. При таймауте результат неизвестен. Сначала выясни статус, не повторяй запись вслепую.

## Добавление продукта

`product-add --name NAME --kcal K --protein P --fat F --carbs C --json` требует все КБЖУ на 100 г: конечные неотрицательные числа, ккал ≤ 1000, БЖУ и их сумма ≤ 100 г. Добавление без бэкапа. Под `BEGIN IMMEDIATE` проверяет нормализованные названия и алиасы, запрещает перезапись и побочные записи триггеров. Допускает штатный SQLite AUTOINCREMENT. Проверяет ровно одну вставку и полный продукт до commit, затем новым read-only соединением после commit. Receipt содержит `product` с ID и КБЖУ, `per_grams`, `saved`, `verified`. Идентичный повтор возвращает `already_exists`; другие значения — `product_conflict`; конфликтующие алиасы/их цели — `alias_conflict`. Ошибка чтения после commit возвращает `saved: true, verified: false`; автоматический повтор запрещён. БД не создаётся и схема не меняется.

Тест `test_product_add.py`: добавление и сохранность остальных данных, нормализация и дубли, неверные значения, конфликты алиасов, побочные триггеры, post-commit сбой, отсутствие БД/схемы, WAL/AUTOINCREMENT, использование нового продукта в записи еды на синтетической БД.

## Безопасность изменения справочника

`product-update` проверяет ID и буквальное название, конечные неотрицательные значения (ккал ≤ 1000, каждое БЖУ ≤ 100 г, сумма БЖУ ≤ 100 г). Меняет только переданные поля КБЖУ одной строки; история еды не пересчитывается.

`alias-add` проверяет существующий продукт и коллизии. Перезапись запрещена. Нормализация алиаса: casefold, е/ё, схлопывание пробелов; `--product` требует буквального названия. Несколько разных полезных алиасов одному продукту разрешены.

`alias-update` меняет только цель одного однозначного существующего алиаса; написание алиаса не меняется. Неоднозначность и совпадение с названием другого продукта отклоняются. Не исправляй устаревшие ссылки автоматически по похожести.

Для обеих update-команд:
1. Preview ничего не пишет; `confirmation` привязан к актуальному состоянию и запрошенной замене. Токен не заменяет согласие владельца.
2. Под `BEGIN IMMEDIATE` CLI повторно проверяет исходное состояние.
3. CLI создаёт одну временную копию SQLite через backup API рядом с БД, проверяет integrity и совпадение содержимого. Другую копию не создавай.
4. Побочные записи триггеров запрещены. После commit — независимая read-only проверка.
5. Копия удаляется только после успешной проверки. При ошибке сохраняется, если была создана; сообщи `backup_path`. `cleanup_failed, verified: true` означает успешное изменение, но неудачное удаление копии.

## Чтение

`products` и `aliases` используют `mode=ro` и `query_only`, не создают БД, не записывают еду и не загружают лекарственные напоминания. Ошибка БД/схемы — не пустой результат и не повод обходить CLI.

`products` ищет по всем словам запроса в названии, normalized_name и алиасах; возвращает полный список без дублей по ID. Совпадение в поиске не доказывает связь алиаса: используй `aliases`.

`aliases` возвращает фактическое `alias → product`, `product_ids` и `dangling`. Пустые `product_ids` означают отсутствующую буквальную цель. Для аудита ссылок проверяй также `len(product_ids) != 1`. Это не проверка смысловой правильности каждой связи.

## Неподдерживаемые безопасные операции

В текущем CLI нет команды удаления/переименования продукта, удаления алиаса, адресного чтения приёма по ID, безопасного редактирования состава приёма и отдельной команды резервирования БД. Добавление продукта поддерживает `product-add`.

`delete --id ID --yes` удаляет приём и позиции, но сам не создаёт страховочную копию и не выдаёт независимый verified receipt. Не запускай его до согласования полного цикла: точный scope, разрешённый backup API, проверка копии, удаление, адресная проверка, удаление копии только после успеха. При отсутствии разрешённого штатного способа — сообщи ограничение и отдельно согласуй техническую доработку или обслуживающий скрипт и его доступ к БД. Одна просьба исправить данные не разрешает прямой SQL.
