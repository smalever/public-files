# Консервы, фото этикетки и добавление нового продукта

## Когда применять
- Пользователь прислал фото банки или этикетки.
- Название блюда расплывчатое, но на упаковке видны БЖУ/ккал.
- В базе нет точного совпадения для готового консервированного продукта.

## Порядок действий
1. Считать с фото **название продукта** (и при необходимости производителя) и **пищевую ценность на 100 г**.
2. Если на фото читаются все 4 значения (ккал, Б, Ж, У), использовать их как основной источник (приоритет выше веб-источников).
3. Если на этикетке не указан один из макросов (часто углеводы на ГОСТ-консервах), не подставляй `0` и не выводи его из калорийности без согласия: предложить через `clarify` варианты — поставить `0`, поискать карточку этого производителя через SearXNG или ввести значение вручную.
4. При согласии на веб-поиск по конкретному бренду не затягивать цепочку 6-секундных запросов: достаточно 1 прочитанного совпадения бренда или 2 неудачных попыток (403/TLS/пустой ответ), после чего вынести найденное значение на подтверждение в `clarify` — каталоги продуктовых сетей часто блокируют чтение.
5. Добавить новый продукт через `$PY $CLI product-add --json`. Если название в базе включает бренд или уточнение, а пользователь называет продукт короче, добавить короткий алиас через `$PY $CLI alias-add --json`.
6. Если пользователь также просил записать приём пищи (а не только пополнить базу), повторить `$PY $CLI meal --json` с точным названием.

## Пример структуры записи
- С этикетки: **белки 6,0 г**, **жиры 16,0 г**, **углеводы 16,0 г**, **232 ккал на 100 г**.
- Продукт (`product-add`): `Каша гречневая с говядиной консервы`
- Короткий алиас (`alias-add`): `каша гречневая с говядиной`
