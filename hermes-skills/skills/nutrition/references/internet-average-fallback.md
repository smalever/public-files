# Интернет-fallback для отсутствующего продукта

Используй только если продукт и однозначный эквивалент отсутствуют в базе, а пользователь явно разрешил интернет-поиск.

## Алгоритм

1. Зафиксируй точный тип продукта, состав и способ приготовления.
2. Загрузи `web-search-fallbacks`; через поиск/reader SearXNG MCP найди до трёх сопоставимых источников с КБЖУ на 100 г, соблюдая его бюджет. При отказе не меняй транспорт.
3. Исключи бренды, рецепты и варианты, не соответствующие запросу пользователя.
4. Если источники описывают один тип продукта, вычисли среднее `kcal / protein / fat / carbs` через `terminal` или `execute_code`.
5. Округли калории до целого, БЖУ — до 0.1 г.
6. Добавь продукт через `product-add` с суффиксом `(средняя оценка)` в названии (например, `Курица жареная (средняя оценка)`) — `normalized_name` сформируется CLI автоматически. Сразу свяжи короткое название без суффикса через `alias-add --alias "курица жареная" --product "Курица жареная (средняя оценка)" --json`.
7. Повтори `nutrition.py meal --json` со всем исходным списком. Verified post-commit receipt достаточен; отдельный SELECT не нужен. При неизвестном исходе — точечная read-only проверка без слепого retry.
8. Сообщи пользователю, что использованы средние интернет-значения.

## Ограничения

- Не смешивай разные рецептуры, бренды и способы приготовления.
- Не подставляй похожий продукт вместо отсутствующего.
- Если сопоставимых данных мало, явно обозначь неопределённость и число источников; не представляй один источник как среднее нескольких. Если надёжная оценка невозможна, запроси этикетку, рецепт или уточнение вместо выдуманного среднего.
- Если точный продукт уже есть в базе, используй его вместо создания дубля.
