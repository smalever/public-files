# Nutrition

## Когда использовать

Используй скилл, когда пользователь просит:
- записать завтрак, обед, ужин или перекус;
- показать калории или БЖУ продукта;
- показать съеденные калории, БЖУ и приёмы пищи за сегодня, конкретную дату или период;
- добавить продукт в справочник;
- исправить или удалить запись питания.

## Обязательные правила

1. Источник КБЖУ — `food_db`, точный алиас или этикетка пользователя.
2. Не считай КБЖУ из головы и не подменяй блюдо похожим по названию.
3. Не сохраняй частичный приём пищи: сначала разреши все неизвестные продукты, затем повтори `meal` со всем исходным списком.
4. Интернет используй только с разрешения пользователя и только после проверки базы и алиасов. Если поисковики блокируют бота — навык `web-search-fallbacks`.
5. Не говори «записал», пока запись не найдена в `nutrition` и её состав — в `nutrition_items`.
6. Удаление записи требует явного подтверждения пользователя.

## Формат приёма пищи

Типы:

| Пользователь | `--meal` |
|---|---|
| завтрак | `breakfast` |
| обед | `lunch` |
| ужин | `dinner` |
| перекус | `snack` |

Формат `--items`:
- продукты разделяются запятой;
- каждый элемент заканчивается весом без пробела: `название 120г`;
- точка с запятой не используется.

Пример:

```text
картошка жареная 150г, свинина жареная 200г, кофе с молоком 300г
```

Если пользователь не указал дату, **не передавай `--date` в `meal`**: CLI сам берёт текущую дату по Москве непосредственно при записи. Не копируй дату из предыдущего вызова или ответа — она может устареть после полуночи. Если дата указана явно (включая «вчера»), вычисли её от свежего системного времени в Москве и передай `--date YYYY-MM-DD`. Если владелец ел до полуночи, а пишет после — это явная дата: передай `--date` вчерашнего дня. При проверке записи без явной даты сверяй `date` и фактическую московскую дату в момент вызова, а не с ранее сохранённой датой.

## Главный pipeline записи

1. Определи тип приёма пищи. Дату для `--date` вычисляй только если пользователь явно указал её; иначе оставь выбор даты CLI.
2. Сохрани исходный полный список продуктов.
3. Сформируй строгую строку `--items`.
4. Запусти:

```bash
# Дата не указана пользователем: CLI берёт текущую дату по Москве
$PY $CLI meal --meal snack --items "продукт 100г, продукт 200г"

# Пользователь явно указал дату
$PY $CLI meal --meal snack --date YYYY-MM-DD --items "продукт 100г, продукт 200г"
```

5. Обработай результат по таблице ниже.
6. Если продукты пришлось уточнять или добавлять, повтори `meal` **один раз со всем исходным списком**, используя разрешённые названия или алиасы.
7. Проверь новую запись и её позиции в БД; при неуказанной дате не подставляй дату из предыдущей команды. Сверь дату записи с московской датой в момент выполнения `meal` (особенно при переходе через полночь). Если дата разошлась — сообщи об ошибке и не заявляй, что запись за сегодня корректна.
8. Только после успешной проверки сообщи результат пользователю.

## Обработка результата `meal`

| Результат | Действие |
|---|---|
| Успех | Проверить запись и состав в БД |
| `product_not_found` | Разрешить каждый неизвестный продукт по decision tree ниже; частичную запись не считать успехом |
| `fuzzy_match` | Автоматически принять только однозначный вариант того же продукта, состава и способа приготовления; иначе спросить |
| `multiple_matches` | Выбрать автоматически только при однозначном соответствии; иначе показать варианты пользователю |

### Критерий однозначного совпадения

Автоматический выбор допустим, только если одновременно выполняется всё:
- найден один подходящий кандидат;
- совпадает тип продукта или блюда;
- совпадает способ приготовления, если он указан;
- не меняется значимый состав.

Сырой, сухой, готовый, отварной и жареный варианты считаются разными. Для обычного веса гарнира без слов «сухой» или «сырой» выбирай готовый/отварной вариант либо существующий точный алиас.

Составное блюдо нельзя выбирать по совпадению одного слова: `макароны с мясом` не равны `макаронам с сыром`.

## Decision tree для неизвестного продукта

Выполняй сверху вниз и остановись на первом подходящем варианте.

1. **Точный продукт или алиас найден** — используй его.
2. **Найден один однозначный эквивалент** — используй точное имя или подтверждённый алиас.
3. **Найдено несколько вариантов либо различаются состав/приготовление** — спроси пользователя.
4. **Пользователь дал этикетку или КБЖУ на 100 г** — добавь продукт по этим данным.
5. **Это домашнее составное блюдо без точных данных** — предложи приблизительную оценку. Только после согласия пользователя найди 3–5 сопоставимых интернет-источников и усредни значения; подробности в `references/generic-dish-average-fallback.md`.
6. **Пользователь явно разрешил интернет-поиск для обычного продукта** — найди минимум 3 сопоставимых источника; подробности в `references/internet-average-fallback.md`.
7. **Данных всё ещё недостаточно** — запроси этикетку, КБЖУ на 100 г или уточнение варианта.

### Поиск по базе и алиасам

Не используй SQLite `LOWER()` для кириллицы. Ищи через Python `str.lower()`; подробности в `references/sqlite-cyrillic-lower-pitfall.md`.

Ищи по **одному значимому корню** или точной подстроке целиком (`'холод'`, `'кефир'`), а не по фразе с предлогами: разбиение «кофе с молоком» по словам даёт сотни ложных совпадений от «с».

```bash
$PY - <<'PY'
import os, sqlite3
q = 'НАЗВАНИЕ'.lower()
path = '/opt/data/personal/nutrition/nutrition.db'
conn = sqlite3.connect(path)
conn.row_factory = sqlite3.Row
for table, sql in {
    'food_db': 'SELECT id, product, normalized_name, kcal, protein, fat, carbs FROM food_db',
    'food_aliases': 'SELECT alias, product FROM food_aliases',
}.items():
    print(f'--- {table} ---')
    for row in conn.execute(sql):
        text = ' '.join(str(v or '') for v in row).lower()
        if q in text:
            print(dict(row))
conn.close()
PY
```

## Добавление продукта

Добавляй продукт только после проверки, что эквивалента нет.

```bash
$PY - <<'PY'
import os, sqlite3
path = '/opt/data/personal/nutrition/nutrition.db'
product = 'Полное название продукта'
normalized = 'короткое название'
kcal, protein, fat, carbs = 123, 1.2, 3.4, 5.6
conn = sqlite3.connect(path)
row = conn.execute(
    'SELECT id FROM food_db WHERE product=? OR normalized_name=?',
    (product, normalized),
).fetchone()
if row is None:
    cur = conn.execute(
        'INSERT INTO food_db (product, kcal, protein, fat, carbs, normalized_name) VALUES (?,?,?,?,?,?)',
        (product, kcal, protein, fat, carbs, normalized),
    )
    print('inserted', cur.lastrowid)
else:
    print('exists', row[0])
conn.commit()
conn.close()
PY
```

Для брендированного продукта:
- `product` — полное название с упаковки;
- `normalized_name` — короткая форма;
- КБЖУ — с упаковки, не из интернета.

## Алиасы

Добавляй короткий алиас, если пользователь регулярно использует однозначное разговорное название. Не создавай алиас по сомнительному fuzzy match и не держи несколько почти одинаковых алиасов. Соглашения: `references/alias-conventions.md`.

```bash
$PY - <<'PY'
import os, sqlite3
path = '/opt/data/personal/nutrition/nutrition.db'
conn = sqlite3.connect(path)
conn.execute(
    'INSERT OR REPLACE INTO food_aliases (alias, product) VALUES (?, ?)',
    ('короткое название', 'Полное название продукта'),
)
conn.commit()
conn.close()
PY
```

## Проверка после записи

```bash
$PY - <<'PY'
import os, sqlite3
DATE = 'YYYY-MM-DD'
MEAL = 'snack'
path = '/opt/data/personal/nutrition/nutrition.db'
conn = sqlite3.connect(path)
conn.row_factory = sqlite3.Row
row = conn.execute(
    'SELECT id, date, meal, total_kcal, total_protein, total_fat, total_carbs '
    'FROM nutrition WHERE date=? AND meal=? ORDER BY id DESC LIMIT 1',
    (DATE, MEAL),
).fetchone()
print(dict(row) if row else None)
if row:
    for item in conn.execute(
        'SELECT product, grams, kcal, protein, fat, carbs '
        'FROM nutrition_items WHERE nutrition_id=? ORDER BY id',
        (row['id'],),
    ):
        print(dict(item))
conn.close()
PY
```

Проверка успешна, только если найдена строка `nutrition` и ожидаемые позиции `nutrition_items`.

## Просмотр съеденного и статистики

Для просмотра приёмов пищи, калорий и БЖУ используй команду `summary` CLI (без сырых inline-скриптов):

```bash
# За сегодня
$PY $CLI summary

# За конкретную дату
$PY $CLI summary --date YYYY-MM-DD

# Сводка за период (например, за 7 дней)
$PY $CLI summary --days 7
```

## Исправление и удаление

1. Найди и покажи пользователю запись: `id`, дату, приём пищи, калории и состав.
2. Перечисли, что будет удалено.
3. Дождись явного подтверждения.
4. Удали запись:

```bash
$PY $CLI delete --id ID --yes
```

5. Если нужна замена, запиши исправленный полный приём пищи и снова проверь БД.

## Ответ пользователю

После обычной записи:

```text
Записал.

Перекус — 75 ккал
- лечо — 150 г
```

Если скрипт вернул напоминание о приёме лекарств (`💊 Прими ... лекарства:`), обязательно добавь этот блок и рекомендации по еде в конец ответа.
Скрипт оценивает **сумму БЖУ всей еды, записанной за последние 60 минут** (включая текущую запись), а не калории одной записи. В напоминании — только непринятые препараты `food` = with/after/any; препараты «до еды» напоминают брифы, здесь они лишь упоминаются строкой «⏰ До еды, ещё не отмечено…».
Пороги — мягкие подсказки 💡, без запретов (правила по действующему веществу — `FOOD_RULES` в `medication_reminder_helper.py`; срабатывают, только если препарат есть в схеме владельца):
- метформин: полноценная еда ≥ 200 ккал (состав не важен);
- омега-3 / коэнзим Q10: жиры ≥ 10 г;
- магний: ≥ 100 ккал;
- остальные препараты по еде не проверяются.
Вывод скрипта передавай как есть, не усиливай подсказки до запретов.
Если в этот период нет непринятых таблеток «с едой», напоминание не выводится.

### Подтверждение приёма таблеток
«Принял всё» → `$PY $CLI take-meds`; «принял X и Y» → `$PY $CLI take-meds --names "X, Y"`. Правила и статусы — навык `health-tracker`, раздел «Лекарства».

Если после успешной записи еды подсистема напоминаний не загрузилась или завершилась ошибкой, `nutrition.py` сохраняет приём пищи, но печатает явное предупреждение в `stderr` вида `⚠️ Не удалось ... лекарства: <тип>: <ошибка>`. Не скрывай такое предупреждение и не утверждай, что проверка лекарств прошла.

Если нужен выбор:

```text
Нашёл несколько вариантов: X, Y, Z. Какой использовать?
```

Если использована приблизительная интернет-оценка, явно сообщи название продукта, среднее значение на 100 г и что оценка приблизительная.
