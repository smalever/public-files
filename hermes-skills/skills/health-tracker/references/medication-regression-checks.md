# Регрессионная проверка лекарственного контура

## Порядок

1. Прочитай runtime-правила и исходники, найди цепочку: схема → синхронизация → SQLite-fallback → напоминание → подтверждение → журналы → статистика. Не запускай синхронизацию ради просмотра: она пишет данные.
2. Сохрани исходники и их хеши перед согласованной правкой. Разделяй разрешение менять скрипты и разрешение менять личные данные; установка кода не равна выполненной миграции или синхронизации БД.
3. Воспроизведи дефект на синтетических данных. Для точечного теста можно извлечь AST только нужных функций, скомпилировать их без кода верхнего уровня и подставить SQLite `:memory:`, часы и схему. Это проверяет реальные тела функций без импорта production-модуля. Для интеграционного теста используй изолированную копию и подмени все пути до исполнения. AST-проверка не заменяет интеграционную.
4. Напиши утверждение ожидаемого поведения, наблюдай RED, внеси минимальную правку и получи GREEN. Проверка, утверждающая наличие известной ошибки, — диагностический probe, а не проходящий регрессионный тест исправления.
5. Проверь обе ветки чтения: доступная заметка и SQLite-fallback. Успех каталога из заметки не проверяет результат синхронизации.
6. После установки проверь точные рабочие файлы теми же изолированными тестами; отдельно сообщи, выполнялась ли синхронизация и затрагивались ли личные записи.

## Обязательная матрица

- Один препарат утром и в обед; утром и вечером; во всех ежедневных слотах: сохранить каждый приём и его дозировку, `food`, время и примечание.
- Еженедельный утренний препарат вместе с ежедневным вечерним: не превращать недельную дозу в ежедневную. Проверить среду и другой день.
- Одинаковые имена в нескольких незакрытых слотах: напоминание должно показывать каждый приём с понятным слотом. Нельзя дедуплицировать только по имени, даже если дозы одинаковы.
- `before` утром и `with` днём для одного имени: фильтр еды не должен скрывать дневную дозу.
- Повтор явного `slot + names`: вернуть «уже принято», не увеличить число записей. Повтор неоднозначного имени без слота не должен отмечать другой приём; требуется выбор слота либо проверяемая идентичность события.
- «Принял всё» в каждом временном окне и повтор: отметить ровно показанные/ожидаемые слоты, не переносить утреннее на вечер и не создавать дубли.
- Legacy-закрытие утреннего слота: не скрывать одноимённую дневную дозу.
- Плановый препарат: журнал приёмов, напоминания и статистика должны согласованно видеть принятую дозу. Запись только в общий `med_log` этого не доказывает; разовый приём вне схемы проверяй отдельно.
- Валидная пустая схема: не восстанавливать старые назначения из fallback. Ошибочная схема: понятное предупреждение, без частичной перезаписи.

При распределении работ не разрешай двум исполнителям перезаписывать один файл целиком: раздели владение функциями, используй адресные патчи и после объединения выполни общую проверку.
