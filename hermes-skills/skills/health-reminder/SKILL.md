# Брифы здоровья (cron → Telegram)

Строгий форматер: на входе JSON от скрипта, на выходе — короткое Telegram-сообщение по шаблону ниже. Ничего не додумывать и не добавлять блоков, которых нет в шаблоне. Этот файл — единственный источник формата: промпты cron-джобов только ссылаются на него.

Данные и логика лекарств/БД — в `health-tracker`; питание — в `nutrition`. Лекарства в JSON — всегда актуальные из скриптов, не из памяти.

Перед первым запуском собственного Python, диагностикой или тестами прочитай файловым инструментом `/opt/data/home/python-runtime.md`. Форматирование уже полученного JSON не требует запуска скриптов.

## Контур

| Джоба | Скрипт (`/opt/data/scripts/`) | Синхронизация |
|---|---|---|
| 🌅 07:00 ежедневно | `health_reminder_morning.py` | `sync_targets()` |
| 🍽 12:00 ежедневно | `health_reminder_lunch.py` (pre-check, логика в `health_reminder_premeal.py`) | — |
| 🌆 18:00 ежедневно | `health_reminder_dinner.py` (pre-check, та же логика) | — |
| 🌙 20:00 «Итоги дня» | `health_reminder_evening.py` (pre-check) | `sync_medications()` |
| 📊 вс 14:00 | `health_weekly_review.py` | обе |
| при записи еды | `nutrition.py meal` → `medication_reminder_helper.py` | — |

У каждого препарата в `Схема препаратов.md` есть `food`: `before` (до еды) / `with` / `after` / `any`. Препараты `before` напоминают только брифы (07:00, 12:00, 18:00); `with`/`after`/`any` — напоминание при записи еды: до 12:00 утренние, 12–16 утренние+дневные, 16–18 дневные, после 18 дневные+вечерние (без исключений по названиям; пропущенное утро после 16:00 не догоняем, это решает владелец с врачом). Отметки о приёме ставятся по каждому препарату (`med_intake_log`).

У каждой синхронизации один владелец — не добавлять повторные вызовы в соседние скрипты. Расписание/ID — только `hermes cron list`.

## 🌅 Утренний бриф

```
🌅 Утренний бриф ([дата])

📏 Не забудь измерить: [список из measure].

📊 Питание за вчера ([дата]):
Калории: [факт] / [цель] ккал ([статус] [diff])
Белки: [факт] / [цель] г ([статус] [diff])
Жиры: [факт] / [цель] г ([статус] [diff])
Углеводы: [факт] / [цель] г ([статус] [diff])

🍽 Съедено вчера:
- [продукты из yesterday_items]

💡 Разбор и рекомендации на сегодня:
- [разбор КБЖУ с привязкой к вчерашним продуктам]

🍳 Хочешь, подберу вкусное блюдо с учётом текущего КБЖУ? Напиши, что есть дома, — придумаем короткий рецепт.
```

Строку «📏 Не забудь измерить…» выводить только если `measure` не пуст: `pressure` → давление, `pulse` → пульс, `glucose` → глюкозу, `weight` → вес, порядок как в списке. Пустой `measure` — строки нет.

Если `before_meal_meds` не пуст — сразу после строки «📏 …» (или после заголовка, если её нет) вставить блок:

```
💊 До завтрака:
- Название (дозировка)
```

Пустой список — блок не выводить.

Правила:
1. `yesterday_items` пуст или 0 ккал → вместо блоков питания одна строка «Вчера записи питания отсутствовали.» и мягкое напоминание вести дневник.
1a. `targets` пуст или без `kcal` (цели не заданы) → блок «📊 Питание за вчера» без «/ [цель]» и статусов, только факт КБЖУ; «💡 Разбор» — без оценок перебора/недобора. Раз в неделю (по понедельникам) можно добавить строку «🎯 Хочешь, посчитаю цель по КБЖУ — напиши рост, вес, возраст и цель».
2. Перебор жиров/углеводов/калорий → назвать вчерашние продукты-источники.
3. Недобор белка → указать граммы; не предлагать догонять вчерашний дефицит и не перечислять шаблонные продукты.
4. Метрики — только напоминание измерить, без значений.
5. Рецепт утром не генерировать, интернет не использовать (подбор — навык `recipe-assistant` по ответу владельца).
6. Есть `sync_warnings` → последней строкой: `⚠️ Внимание: ошибка разметки в заметках Obsidian (<текст>). Использована резервная база SQLite.`

## 🍽 12:00 / 🌆 18:00 — брифы «до еды»

Pre-check: если нет непринятых препаратов `food=before` в слоте и нет других напоминаний (`reminders`), печатает `{"wakeAgent": false}` — сообщения нет. Если агент запущен (`mode` = `lunch_premeal` или `evening_premeal`):

```
🍽 Перед обедом прими:          ← для lunch_premeal
🌆 Перед ужином прими:          ← для evening_premeal
- Название (дозировка)
```

Есть `reminders` — после списка отдельными строками. Советов не добавлять.

## 🌙 Итоги дня (20:00)

Pre-check: если за день всё отмечено, печатает `{"wakeAgent": false}`. Иначе JSON `mode=day_summary`, `pending` по слотам (`morning`/`lunch`/`evening`):

```
🌙 Итоги дня — не отмечены препараты:

Утро:
- Название (дозировка)
Вечер:
- Название (дозировка)

Если уже выпил — назови конкретные препараты. «Принял всё» вечером отмечает только дневные и вечерние, не пропущенные утренние.
```

Выводить только слоты из `pending` (подписи: Утро / Обед / Вечер). Не писать «лекарств нет», не добавлять советов. `sync_warnings` → строка предупреждения как в утреннем.

## 📊 Воскресный обзор

Личные коридоры и цели приходят в JSON (`monitoring`, `*.target*`); блок без данных — не выводить, цифры не выдумывать.

1. 🍽 **Итоги питания за 7 дней (среднее в сутки):** ккал и БЖУ; если `nutrition_summary.targets` не null — факт vs цель и дельта, иначе только факт и число дней с записями.
2. 💡 **Фокус питания на неделю:** одна чёткая рекомендация; при наличии `protein_tips` — блок «🥩 *Как легко добрать белок без лишнего жира:*» с 3–4 вариантами.
3. 📉 **Метрики** (только те, по которым есть замеры): вес и темп (`weight_summary.target` — ориентир, если есть), сахар (`glucose_summary.target_range` / `in_target_range`, если есть), среднее АД и скачки (`bp_summary.spikes` выше `spike_threshold`, если есть).
4. 🧪 **Обследования:** `lab_summary` пуст — блок не выводить. `is_due_for_control=true` → «⚠️ Пора запланировать визит в лабораторию» + `recommended_panel` (если пуст — без списка); иначе — «всё планово».
5. 💊 **Терапия:** только если `meds_adherence.total_scheduled` > 0. 100% — «Все приёмы выполнены на 100%!»; иначе дословно `message` + из `missed_list` дни/слоты и пропущенные препараты (`medications`). Напомнить проверить остатки препаратов на 2 недели.
6. `sync_warnings` → предупреждение.
7. Последняя строка: `MEDIA:` + `chart_media` (если не пусто).

## Настройка мониторинга владельца

Цели КБЖУ — `targets:` в `/notes/Моё здоровье/Цели и мониторинг.md`. Личные ориентиры — необязательный блок `monitoring:` там же (читает `/opt/data/scripts/health_monitoring.py`):

```yaml
monitoring:
  protein_range: [100, 120]        # г/сут
  kcal_range: [1800, 2000]
  water_l: [2.0, 2.5]
  glucose_range: [4.5, 6.0]        # ммоль/л
  weight_corridor: [78, 82]        # кг, зелёная зона графика
  weight_start: 90                 # для заголовка графика «с … до …»
  weight_target: 80
  bp_systolic_range: [110, 130]
  bp_diastolic_range: [70, 85]
  bp_systolic_spike: 140           # порог «скачка» в обзоре
  measure: [pressure, pulse, weight]   # что напоминать измерить утром
  lab_interval_days: 90            # плановый контроль анализов
  lab_panel: [Общий анализ крови, Глюкоза натощак]
```

Ключи необязательны: нет ключа — соответствующего блока в брифе/графике нет. Значения задаёт владелец (с врачом); бот предлагает правку, показывает её и пишет после подтверждения.

## Включение брифов у нового владельца

Новый бот разворачивается с этими задачами на паузе. Когда владелец заполнил хотя бы цели или схему препаратов и согласился получать брифы:

```bash
hermes cron list                 # найти id 🌅 🍽 🌆 🌙 📊
hermes cron resume <id>          # для каждой выбранной владельцем задачи
```

Пустая схема препаратов — брифы «до еды» и «Итоги дня» молчат (pre-check возвращает `wakeAgent: false`), включать их можно сразу. Время задач меняется через `hermes cron edit <id> --schedule "0 8 * * *"`.

## Поддержка

- Меняется формат JSON → одновременно править скрипт и шаблон здесь; промпты джоб не трогать.
- Логика фильтрации таблеток — только в `medication_reminder_helper.py`.
- Единицы в БД русские (`кг`, `ммоль/л`, `мм.рт.ст`) — не хардкодить английские.
- Cron-скрипты без `argparse` не запускать «для проверки»: читать исходник, синтаксис проверять `ast.parse` текста в памяти, без импорта и исполнения.
- Тесты скриптов запускать только на изолированной копии с синтетическими данными, без production mounts и сети. Общая справка: `/opt/data/home/python-runtime.md`. Пять health jobs используют явный venv-interpreter; self-reexec из скриптов удалён.
- Детали cron (правка промпта, `wakeAgent`, `hermes cron doctor`): `references/cron-integration.md`.
