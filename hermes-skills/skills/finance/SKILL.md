# Finance — Управление финансами

```bash
PY=/opt/data/home/.venv/bin/python
FIN=/opt/data/skills-custom/finance/finance/scripts/finance.py
DB=/opt/data/personal/finance/finance.db   # данные вне скилла
SETTINGS=/opt/data/personal/finance/finance-settings.yaml   # счета владельца
```
Основной сценарий — ручная запись расходов через `scripts/finance.py`.

## Быстрый сценарий: записать расход

1. **Дата**: если пользователь не указал дату — сегодня (`date +%F`). **Pitfall:** записи у полуночи могут получить следующую дату — если покупка была до полуночи, а записываем после, указать `--on` явно.
2. **Счёт**: по правилам из «Счетов» ниже; если счёт не указан — счёт по умолчанию из настроек (`--account` можно не передавать).
3. **Сумма**: рубли в `--amount`; расход `--sign neg`, доход `--sign pos`.
4. **Категория**: техническое имя из `CATEGORY_NAMES`.
5. **Vendor / note**: по разделу «Vendor / category / note».
6. Выполнить `finance.py add` (пример в «Командах CLI»).
7. Проверить запись через `finance.py list` за нужную дату/счёт.

## Счета

Счета — данные владельца, а не код: они лежат в `finance-settings.yaml` рядом с базой. Список, валюты, счёт по умолчанию и разговорные названия — только из CLI, не из памяти:

```bash
$PY $FIN accounts          # текстом
$PY $FIN accounts --json   # id, name, currency, aliases, default_account
```

- Файла нет → работают счета по умолчанию `card` (Карта, он же дефолт) и `cash` (Наличные).
- Счёт выбирается по `aliases` из настроек; явное указание пользователя приоритетнее дефолта. Неоднозначно — переспросить.
- Валюта определяется счётом (по умолчанию `RUB`). Отчёты и балансы выводят итоги раздельно по валютам и никогда не складывают RUB с USD.
- Новый счёт, переименование, смена дефолта — правка `finance-settings.yaml` по `references/settings.md`: показать изменение, получить подтверждение, затем `accounts` для проверки. Существующие транзакции хранят технический id счёта — id не переименовывать.

## Суммы

CLI принимает рубли в `--amount`, БД хранит копейки.

- `1200`, `1 200`, `1.200` → 1200 ₽.
- `1200,50`, `1200.50` → 1200.50 ₽.
- В русском бытовом контексте `1,200` без явных копеек считать 1200 ₽.

**Pitfall:** при прямой работе с SQLite `amount` всегда в копейках: `-400.00 руб` в CLI = `-40000` в SQL. Подробности: `references/sqlite-amount-scale.md`.

## Категории

Источник правды: `CATEGORY_NAMES` в `scripts/category_map.py`. Справочник с пояснениями: `references/categories.md`.

Категории в командах и БД — только технические имена; русские названия используются только в выводе.

## Vendor / category / note

- `vendor` — магазин или место покупки: `"Чижик"`, `"Пятёрочка"`, `"Аптека"`, `"Лукойл"`.
- `category` — техническая категория: `groceries`, `health`, `fuel`.
- `note` — детали покупки: `"продукты"`, `"лекарства"`, `"солярка"`, `"замена колодок"`. Если деталей нет — не указывать.

Антипаттерны:

- `vendor="Чижик продукты"` — неправильно. Нужно `vendor="Чижик"`, `category=groceries`, `note="продукты"`.
- `vendor="Сигареты"` — неправильно, это товар. Магазин идёт в `vendor`, сигареты — `category=smoking` или `note`.
- `category=tobacco` — неправильно, такой категории нет. Использовать `smoking`.

## Частые правила

- **Чижик**, **Пятёрочка**, **Магнит**, **Мясоедов**, **Рыба**, **Вода** → обычно `groceries`.
- **Аптека** → `health`, `note="лекарства"`, если пользователь не уточнил препараты.
- **Заправка**, **Лукойл**, **Газпром** → `fuel`; топливо не записывать в `auto`.
- **Автосервис**, ремонт, запчасти, ТО → `auto`.
- **Юрист**, **адвокат**, **нотариус**, юридические услуги и оформление юридических документов → `legal`.
- **Электричество, вода, газ** → `category=home`, `vendor` — поставщик, если известен.
- **Ozon/Wildberries** → категория по содержимому товара: съедобное → `groceries`, понятный несъедобный товар — его категория (одежда → `clothing` и т.д.). Пользователь хочет видеть весь «съедобный» расход в продуктах независимо от канала покупки. Смешанная корзина: если есть разбивка сумм — раздельные записи; если разбивки нет — одна запись в `marketplace` с составом в `note` (наугад не делить).
- **Серверы, VPS, хостинг** → `it_services`. Домашний интернет провайдера (Ростелеком, «интернет») → `home`.
- **Подписки** (Озон Премиум, Яндекс Плюс, стриминг) → `subscriptions`, независимо от счёта оплаты.
- **Подарки** («подарок на др …», букеты) → `gifts`.

## Команды CLI

### Добавить транзакцию

Обязательные: `--amount` (рубли), `--cat`.
Опциональные: `--account` (по умолчанию — из настроек), `--sign neg|pos` (по умолчанию `neg`), `--vendor`, `--note`, `--on YYYY-MM-DD`.

```bash
$PY $FIN add \
  --amount 1200 \
  --cat groceries \
  --account card \
  --sign neg \
  --vendor "Чижик" \
  --note "продукты" \
  --on 2026-06-10
```

`add` валидирует `category` и `account` по `CATEGORY_NAMES` / `ACCOUNT_NAMES`.

### Список транзакций

```bash
$PY $FIN list --from 2026-05-01 --to 2026-05-31
$PY $FIN list --account card --limit 10
$PY $FIN list --from 2026-05-01 --json
```

- `--cat` принимает технические имена; `--cat auto_all` — виртуальный фильтр `auto + fuel`, в БД такая категория не хранится.
- Вывод показывает vendor и note вместе в колонке `Магазин / note` как `vendor | note`.

### Баланс и статистика

```bash
$PY $FIN balance [--account card]
$PY $FIN stats --period month [--from YYYY-MM-DD --to YYYY-MM-DD]
$PY $FIN stats --period cat
```

В `stats --period cat` есть служебная строка `Автомобиль (с топливом)` = `auto + fuel`.

### Учёт заправок и расхода топлива (л / 100 км)

Для точного учёта топлива с одометром и расчётом «до полного бака» (отсечка):

```bash
# Добавить заправку
$PY $FIN fuel-add \
  --odo 145200 \
  --liters 45 \
  --amount 3000 \
  --account card \
  --vendor "Лукойл" \
  --full

# Список заправок
$PY $FIN fuel-list

# Статистика расхода (л/100 км) и стоимости 1 км
$PY $FIN fuel-stats --from 2026-04-01
```

- `fuel-add` автоматически создаёт запись расхода в `transactions` (категория `fuel`) и параллельно сохраняет метрики в `fuel_log`.
- Флаг `--full` — заправка до полного бака (отсечка); частичная — `--partial`.
- Расчёт среднего расхода (л/100 км) отсекается между первой и последней заправкой «до полного» за выбранный период.

### Удаление транзакции

```bash
$PY $FIN delete --index 1
$PY $FIN delete --last-cat groceries
```

- `--index N` — N-я транзакция от конца по времени (`1` = последняя добавленная).
- `--last-cat CAT` — последняя транзакция категории.

Перед удалением записей по просьбе пользователя соблюдай общее правило безопасности: если операция массовая/destructive — сначала показать объём, получить явное подтверждение и сделать бэкап.

## Импорт выписок

Используется редко. Какие счета импортировать и из каких файлов — `import` в `finance-settings.yaml`. Полная инструкция: `references/import-instructions.md`.

```bash
$PY /opt/data/skills-custom/finance/finance/scripts/import_sber.py --run
$PY /opt/data/skills-custom/finance/finance/scripts/import_ozon.py --run
```

Правила:

- импортёры загружают только расходы; доходы и переводы пропускаются;
- импортёр заменяет данные только своего счёта и лишь если успешно распарсил хотя бы одну строку;
- без аргументов или с `--help` импортёр показывает справку и ничего не меняет в БД; реальный импорт — только явный флаг `--run`.

**Pitfall:** не запускать импортёры «просто так» для проверки доступности скрипта. Smoke-check — запуск без аргументов или `--help`; `--run` — только по явной задаче пользователя.

## Перекатегоризация операций

Перенос прошлых платежей в новую категорию — редкая операция. Полная пошаговая процедура: `references/recategorization.md`.

Кратко: найти кандидатов (включая обезличенные банковские описания) → показать список с датой, суммой, счётом → получить явное подтверждение → добавить категорию в `CATEGORY_NAMES` и `references/categories.md` → бэкап через SQLite backup API → точечный `UPDATE` в одной SQL-транзакции с проверкой числа строк (при расхождении rollback) → проверить результат через `list --cat`.

**Pitfall:** совпадение только по общей категории или обезличенному описанию (`Прочее`, `Оплата по QR-коду`) не доказывает назначение платежа. Такие записи оставлять без изменений до подтверждения пользователя.

## Структура данных

Таблица `transactions`:

- `id` TEXT PK — уникальный id операции.
  - ручной ввод: `manual_{account}_{ts}_{amount_abs}[_N]`
  - импорт Сбера: `sber_{account}_{ts}_{amount_abs}[_N]`
  - импорт Озона: `ozon_{account}_{ts}_{amount_abs}[_N]`
- `ts` INTEGER — timestamp в мс
- `date` TEXT — `YYYY-MM-DD`
- `amount` INTEGER — сумма в копейках, отрицательная = расход
- `currency` TEXT — `RUB`
- `category` TEXT — техническая категория
- `account` TEXT — технический счёт
- `vendor` TEXT — магазин/место
- `note` TEXT — детали покупки или сырой текст операции

## Для изменения скриптов

- Новые helper-функции размещать рядом с существующими helper-функциями до `cmd_*`.
- Не заменять существующую рабочую логику без необходимости.
- Категории — в `scripts/category_map.py` (+ `references/categories.md`). Счета, файлы выписок и личные шаблоны магазинов — только в `finance-settings.yaml`, не в коде.
- Для сложной очистки/аудита БД см. `references/db-cleanup-audit.md`.
