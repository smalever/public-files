# Аудит и очистка finance.db после кривого импорта

Использовать, когда база уже содержит исторический мусор от старых импортёров: переводы, движения средств, займы/кредитные записи, сырые `vendor`.

## Безопасная последовательность

1. **Перед любым `DELETE` / `UPDATE` обязательно сделать backup БД**
   - пример имени: `finance.db.bak.pre-clean.YYYYMMDD-HHMMSS`
2. **Сделать read-only аудит**
   - посчитать общее число записей
   - отдельно посчитать расходы / доходы
   - проверить невалидные `category` / `account`
   - собрать выборки подозрительных записей
3. **Показать пользователю вывод аудита**
   - что именно выглядит лишним
   - сколько записей будет затронуто
4. **Только после явного подтверждения** выполнять `DELETE` / `UPDATE`
5. **После чистки сразу сделать post-check**
   - сколько записей осталось
   - сколько удалено
   - остались ли переводоподобные / кредитные записи

## Что считать подозрительным

### Переводы / движения средств
Искать по `vendor` и `note` паттерны вида:
- `Перевод`
- `Перевод собственных средств`
- `Перевод на карту`
- `Перевод с карты`
- `Перевод СБП`
- `СБП. Получатель:`
- `СБП. Отправитель:`

### Займы / кредитные движения
Искать по `vendor` и `note`:
- названия кредитных счетов владельца (`finance.py accounts`)
- `МКК`
- `займ`
- `кредит`

### Сырой `vendor`
Признаки:
- банковская формулировка вместо магазина
- номера заказов / ID вместо названия магазина
- обобщённые категории вроде `Супермаркеты`, `Прочие операции`, `Коммунальные платежи...`
- сырые merchant-строки вроде `PYATEROCHKA ...`, `MAGNIT ...`, `EBK_PROEZD ...`

## Нормализация `home` / коммунальных платежей
Если запись явно относится к оплате электричества, воды, газа:
- `category` должна быть `home`
- `vendor` — название поставщика (если его нет в `vendor_patterns` настроек — предложить добавить)
- исходную банковскую строку лучше сохранять в `note`

Признаки: название поставщика, лицевой счёт в описании, общее `Коммунальные платежи, связь, интернет.`

## Важно

- Если остаются **положительные** записи после удаления переводов, не удалять их автоматически.
- Сначала проверить: это может быть не перевод, а **возврат** или особый тип marketplace-операции.
- Для массовой нормализации `vendor` предпочитать отдельный шаг после очистки, а не смешивать всё в одну транзакцию.
