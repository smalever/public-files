# Перекатегоризация операций (перенос прошлых платежей в новую категорию)

Редкая операция. Выполнять по шагам, без пропусков.

1. Найти кандидатов широким поиском по `vendor` и `note`: учитывать синонимы, сокращения и связанные услуги.
2. Дополнительно просмотреть операции исходной общей категории (`other_expense`), чтобы обнаружить релевантные банковские описания без ожидаемых ключевых слов.
3. Отделить явно подтверждаемые записи от обезличенных (`Прочее`, `Оплата по QR-коду`): не переносить сомнительные операции без пояснения пользователя.
4. До изменений показать кандидатов с датой, суммой, счётом и назначением; отдельно отметить похожие возможные дубли.
5. Получить явное подтверждение конкретного набора записей.
6. Добавить техническую категорию в `CATEGORY_NAMES` (`scripts/category_map.py`) и `references/categories.md`; при наличии устойчивого банковского маркера обновить соответствующий импортный маппинг.
7. Проверить синтаксис и маппинг без создания тестовых транзакций.
8. Создать согласованную резервную копию БД через SQLite backup API.
9. В одной SQL-транзакции проверить наличие всех подтверждённых ID и ожидаемую исходную категорию, выполнить точечный `UPDATE ... WHERE id IN (...) AND category = ...`, проверить точное число строк; при расхождении — rollback.
10. Проверить результат штатным `finance.py list --cat ...`: сумму перенесённых операций и отсутствие этих ID в старой категории.

## Pitfalls

- Совпадение только по общей категории или обезличенному банковскому описанию не доказывает назначение платежа. Такие записи оставлять без изменений до подтверждения пользователя.
- Не создавать тестовые транзакции для проверки маппинга.
