# Web Search Fallbacks

## Когда использовать

Используй, когда нужно найти источники в вебе, а поисковая выдача недоступна штатными средствами: `web_extract` отдаёт пустоту/блокировку, поисковики отвечают капчей, пустой оболочкой или мусорной выдачей. Класс задач: любой ресёрч (КБЖУ продуктов, цены, новости, документация), где нужен именно поиск, а не восстановление одной конкретной страницы.

Разделение с встроенным `blocked-page-recovery`: он восстанавливает **одну известную страницу** (Wayback, archive.today, API-pivot); этот навык **ищет источники заново**, когда недоступен сам поиск. Если нашёл URL, но он не открывается — переходи к `blocked-page-recovery`.

## Лестница доступа

Иди сверху вниз и переходи дальше после первой неудачи. Не долбишь один движок повторными запросами.

1. **Штатный `web_extract`** на известных или угаданных URL. Дёшево и даёт чистый markdown. Если вернул контент — готово.
2. **Поисковик через curl с браузерным UA.** Сначала дешёвая проба доступности, потом полный запрос:

```bash
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0 Safari/537.36"
curl -sL --max-time 25 -A "$UA" -H "Accept-Language: ru,en;q=0.8" \
  "https://search.brave.com/search?q=ЗАПРОС" -o /opt/data/cache/scratch/serp.html -w "%{http_code}\n"
```

   Кириллицу в параметрах кодируй процентно (`холодец` → `%D1%85%D0%BE%D0%BB%D0%BE%D0%B4%D0%B5%D1%86`).
3. **Валидация выдачи.** HTTP 200 не означает, что это результаты поиска. Проверь: `<title>` содержит смысл запроса; есть уникальные внешние hrefs (не домены поисковика), хотя бы ~5. Иначе движок мимо — следующий кандидат без ретраев.
4. **Сбор ссылок из выдачи.** Регуляркой вытащи все `href="http..."`, отбрось домены самого поисковика и служебные; продедуплицируй. Возьми 3–5 кандидатов под задачу (отсей бренды/нерелевантное по заголовкам и сниппетам рядом со ссылками).
5. **Прямое скачивание источников.** Даже если `web_extract` не смог открыть сайт, curl с браузерным UA часто проходит (и наоборот):

```bash
for u in "https://site-a.ru/page" "https://site-b.ru/page"; do
  code=$(curl -sL --max-time 12 -A "$UA" -o "/opt/data/cache/scratch/src_$(basename $u .html)" -w "%{http_code}" "$u")
  echo "$code $u"
done
```

6. **Парсинг в Python:** вырезать `<script>`/`<style>`, снять теги, `html.unescape`, схлопнуть пробелы; искать нужные значения регэкспами возле ключевых слов. Обязательно проверяй контекст и единицы («на 100 г», валюта, дата), а не первое попавшееся число.

## Статусы движков (датированные наблюдения, не вечные правила)

Доступность поисковиков для ботов ротируется. Перед использованием лога — быстрая перепробка (шаги 2–3 лестницы), она занимает секунды. Подробный лог проб с командами и выводом: `references/probe-log-2026-08.md`.

## Питфоллы

- **Фальшивый успех движка:** страница 200 с десятками килобайт может быть капчей, согласием на cookies или мусорной выдачей без органики. Валидируй по заголовку и числу внешних ссылок.
- **Фальшивый успех источника:** 200 от сайта ещё не значит, что там искомый контент — перед парсингом проверь наличие ключевых слов темы.
- Не отправляй cookies/Authorization через прокси-релеи; браузерный UA — можно.
- Разные каналы блокируют по-разному: сайт может быть закрыт для `web_extract`, но открыт для curl+UA. Пробуй оба канала, прежде чем списывать источник.
- Один движок не ответил — иди дальше по списку; повторные попытки того же URL почти никогда не помогают.
